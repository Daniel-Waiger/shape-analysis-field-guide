# 10 · Phenotype Lab

> **In one breath.** The [Phenotype Lab](../lab/) takes six labeled datasets, from worms to gorilla skulls, and asks each the same question: does shape alone predict the label? It runs the guide's three method families side by side, draws what each one saw, and lets you drag a shape and watch the classifier change its mind. Every number on the page was written by one script with one seed; this chapter reads those numbers out loud, including the dataset where the method loses to a coin flip and the one where the label is not the only thing that separates the groups.

## One rule

The lab lives at `docs/lab/` and is served at <https://daniel-waiger.github.io/shape-analysis-field-guide/lab/>. Its one rule: **no result on the page is typed in by hand.** `scripts/run_lab.py` loads each dataset from the registry, runs the methods and writes `docs/lab/data/<id>.json`; the page only renders those files. Hover any number and it names the script that computed it and when.

The script is deterministic (seed 0). The three cross-validated methods are scored by **stratified, shuffled 5-fold cross-validation** (`StratifiedKFold(5, shuffle=True, random_state=0)`); the reported accuracy is the pooled accuracy of the out-of-fold predictions, stored with the five fold accuracies and their standard deviation (population SD, `ddof=0`). The Fréchet mean and the tangent PCA are fitted once on all shapes (no labels involved); the scaler and the regression are refit in every fold. Every method sees shapes with size removed (`size_information: "removed"` in the JSON): the classical pipeline divides by the Frobenius norm, and PointNet's clouds are each divided by their own RMS radius. Size is measured on its own, by a fourth method that sees nothing else. **Chance** is the fraction of the largest class: always saying "circular" scores exactly chance.

| key | input | pipeline | chapters |
|---|---|---|---|
| `landmarks_lr` | ordered points in correspondence | preshape → align to the Fréchet mean → log map → tangent PCA (variance above $10^{-10}$, at most 40 components) → standardize → logistic regression | 02–06 |
| `spline_lr` | an ordered curve | `BSplineCurve(M).fit` → the $M$ control points → the same geometry on those, without Chapter 07's Gram matrix Φ (the control points are treated as $M$ landmarks) | 07 |
| `size_lr` | the same points, nothing but their size | log centroid size → standardize → logistic regression; a baseline, never a headline (`index.json` excludes it from `best_accuracy`) | 02 |
| `pointnet_probe` | any point set, order ignored, each cloud scaled to unit RMS radius | PointNet + supervised contrastive loss → frozen embedding → linear probe; the untrained twin as a baseline | 08 |

Closed outlines (leaves, red cells) get one more label-free step. Arc-length resampling puts points in correspondence only *up to a cyclic shift*: where each outline starts is wherever the contour tracer or the source file happened to start, and a rotation-only Procrustes cannot undo a shift. `prepare_points` therefore re-roots every outline at the cyclic shift that brings it closest to the Fréchet mean (three rounds of shift, recompute the mean), but keeps the source's start point when at least half of the outlines already start within 10 % of the perimeter of their best shift, because then the start is a landmark that a mean-driven shift would only blur. The JSON records the decision under `cyclic_shift_alignment` and `correspondence`.

## How to read a dataset page

Five panels, in pipeline order, starting from the pixels.

0. **From pixels.** Sample images, where the image license allows it (the worms and the fibroblasts), with a toggle that draws the outlines or landmarks the lab actually uses on top, a caption naming the source file and a credit line; for the other datasets, the reason there are no images and the fetch command. Look here first: the MEF finding below came from building this panel, not from any number.
1. **Raw shapes by class.** Five seeded examples per class, aligned to the mean, in image orientation. If you see no difference here, do not expect the classifier to find a large one.
2. **Aligned cloud.** Up to 400 shapes as dots on the first two tangent-PCA axes, colored by class (Chapter 06). Overlapping colors mean any separation lives in later components.
3. **Mode 1.** The mean with mode 1 at ±1 SD and tiles of explained variance: what the population mostly does, which says nothing about labels PCA never saw.
4. **Results.** Accuracy against chance; the confusion matrix (rows true, columns predicted) with its largest off-diagonal cell highlighted; and the **worst mistakes** (up to three): for the classical tabs the wrong out-of-fold predictions with the highest confidence in the wrong class, for the PointNet tab the wrong predictions on its 25 % hold-out, drawn with that probability. Method tabs switch this panel; each tab's header quotes the method's `protocol` from the JSON.

The **classify** screen puts a shape under your pointer. Drag any landmark (or focus one and use the arrow keys) over the faint mean; buttons load the mean, each worst mistake, or a random shape of each class. Probability bars update as you drag, and a five-step stepper shows what happened to your shape: centroid subtracted, size scaled to 1, the rotation angle onto the mean (Chapter 03), the geodesic distance with the two largest tangent scores, then the regression's logit and probability. Below it sit the three nearest training shapes by geodesic distance, with their true labels. Three engines can do the arithmetic:

- **Fitted weights, JS** (every device): the classical pipeline is a few hundred numbers (mean, PCA directions, one weight vector per class) that `engines/classical.js` evaluates instantly. On load the page re-classifies the stored worst mistakes and warns if it disagrees with Python by more than $10^{-3}$ (shipped data: about $6 \times 10^{-5}$).
- **PointNet, ONNX** (every device, phones included): the trained network, exported to `models/<id>.onnx`, runs in the browser through ONNX Runtime Web; its embedding goes through the fitted probe weights. The cloud is centered and divided by its own RMS radius first, exactly as in training, so the size of what you drew does not matter. "Shuffle the points" reorders the cloud and reports the largest change in the embedding, which should be zero up to floating-point noise (Chapter 08; the JSON's `permutation_max_delta` is below $10^{-5}$ on every dataset).
- **shapekit, Pyodide** (desktop only, about 20 MB): a "Run it yourself" panel loads Python in a web worker, installs the `shapekit` wheel and re-runs the classical cross-validation with the $M$, components and $C$ you choose. It reads the data files from `docs/lab/data/files/`, byte-identical copies of the redistributable files in `data/` (a test keeps them identical), so it works on GitHub Pages as well as from a local `docs/` server.

## The findings, dataset by dataset

All numbers are from the JSON files computed on 2026-10-22 (the second run; the first run's numbers appear below only as cautionary tales, marked as such); `mef.json` was recomputed twice on 2026-10-23, to add the roundness diagnostic and then to measure its circularity on loop-ordered points, with every method's numbers unchanged. Classical and size-only numbers are 5-fold CV on all shapes. A PointNet number labeled "hold-out" is a linear probe fitted on the embeddings of the training part and scored on a stratified 25 % hold-out (`random_state=0`) that nothing touched during training: the 75 % training part is split again, stratified, into *fit* (80 %) and *select* (20 %), the network trains on fit, and the epoch is chosen by the probe's score on select, reported as `accuracy_select`. The next section says why a hold-out number is still a different kind of number from a cross-validated one.

**C. elegans, live versus dead** (1377 worms, 12 landmarks; chance 0.5795). Landmarks + LR: **0.8017** (fold SD 0.0071). The confusion matrix is lopsided: 535 of 579 dead worms are called dead (92.4 %), but 229 of 798 live worms are also called dead (28.7 %). Chapter 06 explains why: the classes share a mean shape and differ in *spread*. [Inference] A dead worm is a nearly straight rod; a live worm can be anything from a rod to a tight C, and a straight live worm is indistinguishable from a dead one. Note also that BBBC010's labels come from the treated and untreated control wells, which the set describes as "predominantly" live or dead, so some "live" worms may look dead for that reason rather than for any failure of the method. Spline + LR (M = 6, 8 components): **0.7778**, same asymmetry pushed further (11 dead called live, 295 live called dead). Size only: **0.7466** (SD 0.021; median centroid size 130.3 px dead, 112.5 px live), so a worm's size says almost as much as its shape; the two are not combined anywhere in the lab. PointNet + probe, hold-out: **0.8783**, 0.0766 above the landmark result, with the twelve landmarks fed as an unordered cloud of unit size; the epoch was chosen on the select slice at 10 of 40 (`accuracy_select` 0.8647), and on the 345 held-out worms the matrix is 129/16 and 26/174. One thing tempers that: the *untrained* network's probe scores 0.8725 on the same hold-out, so training added 0.0058, about two worms. *Cautionary tale.* The first run divided every cloud by one dataset-wide scale, so PointNet kept size, and it chose the epoch on the hold-out it reported: it scored 0.887 and the chapter had to explain that much of the margin was size. With size removed and the epoch chosen elsewhere, the margin over the landmark route is 0.0766, and what remains of it is [Inference] the probe's freedom to use all 256 embedding dimensions where the classical route keeps 20 components.

**Mouse fibroblasts, wild-type versus LMNA−/−, genotype confounded with substrate** (1200 cells, 120 unordered points; chance 0.5). The numbers in this paragraph are what the lab computed, but they measure how well two *groups of cells* can be told apart, and the next paragraph explains why that is not the same as two genotypes. Only PointNet and the size baseline apply: without correspondence there is nothing for Procrustes to grip. Hold-out probe **0.9167** (matrix 138/12 and 13/137 on the 300 held-out cells), untrained **0.92**: the select slice picked epoch 4 of 60 (`accuracy_select` 0.9389), and the trained network does *not* beat its untrained twin on the hold-out. A random PointNet with a linear probe already separates these outlines, as Chapter 08 found; a 60-epoch CPU run (one to two minutes of wall-clock time; the JSON's `timing` block records it, and it changes from run to run) adds nothing measurable here. Size only: **0.7792** (median 566 px wild-type, 346 px LMNA−/−), a large difference that the unit-size input to PointNet never sees. *Cautionary tale.* The first run reported 0.9533 for this dataset: the input kept size, and the epoch was the best of 61 scored on the reported hold-out. The display panels order the points by angle around the centroid so a mean and a mode can be drawn; the JSON marks this as display only.

**What the classifier is most likely seeing.** The two groups were not grown the same way. Matching the tutorial's outlines field by field against the original images (kukionfr/Micropattern_MEF_LMNA_Image, commit `7cbe667`) placed 14 of 14 sampled wild-type fields in the folder `Control/LMNA++1`, cells spreading freely on an unpatterned surface, and 14 of 14 sampled LMNA−/− fields in `Circle/LMNA--1`, cells confined to a circular micropattern. Each field was compared with the images of the same xy number in all twelve of the repository's folders, and no other folder registered (the method and its numbers are in `ATTRIBUTION.md`). [Inference] The 86 + 86 fields not sampled come from the same two folders. If so, genotype and substrate change together in this dataset, and so does everything else that differs between the two folders (culture dish, day, imaging session; the repository does not say what its folder suffixes 1 and 2 mean). [Inference] A cell held on a circle comes out round, and a cell spreading freely comes out irregular, with protrusions. The outlines say the same. The median circularity is 0.88 for LMNA−/− and 0.32 for wild-type: $4\pi A / P^2$, 1 for a circle, of the 120 points joined in loop order, a nearest-neighbor walk tidied by 2-opt (`shapekit.contours.order_loop`). The median axis ratio is 1.17 against 1.64. A first version of this diagnostic joined the points in angle order around the centroid; an outline with protrusions zigzags that way, and wild-type came out at 0.11. Those two hand-made numbers, circularity and axis ratio, with a logistic regression classify the cells at **0.94**: 5-fold CV, same folds, fold SD 0.0057, matrix 562/38 and 34/566. The page lists it next to the methods as "roundness only", a diagnostic, not a method. That is a little above PointNet's 0.9167 and its untrained twin's 0.92, but one is cross-validated and the other two are hold-out numbers, so read the three as level, not as a ranking. [Inference] The simplest reading is that the classifier sees round versus spread, which the micropattern alone would be expected to produce, and the lab cannot say how much of 0.9167, if any, is genotype. The size baseline is caught the same way: [Inference] a circle limits how far a cell can spread, so a 566 versus 346 px difference in median centroid size is what the substrate would predict too. The question can be asked properly. The original repository has both genotypes on each substrate (`Control`, `Circle` and `Triangle`, each with LMNA++ and LMNA−− in folders suffixed 1 and 2, 100 fields per folder in its file tree), so wild-type and LMNA−/− cells on the same pattern can be compared. That needs new segmentation and has not been done.

**The lab's second lesson.** The brains (below) show that a number can mean nothing because 28 subjects cannot support 22 shape dimensions. The fibroblasts show the other failure: a number can be high and reproducible and still answer a different question, because something besides the label differs between the groups. Cross-validation cannot catch this; it checks that a rule generalizes to new cells *from the same two groups*. Before reading an accuracy as a phenotype, list what varies besides the label: substrate, dish or plate, day, microscope, imaging settings, who segmented. No number flagged this one. It was found by looking at the raw images: building the page's "0 · From pixels" panel meant finding the tutorial's two sample fields in the original repository, their checksums named `Control/LMNA++1` and `Circle/LMNA--1`, and a field-by-field check of 28 fields followed. That is why panel 0 comes before every number on the page.

**Brain landmarks, schizophrenia versus control** (28 subjects, 13 landmarks; chance 0.5). Landmarks + LR: **0.3929**, below chance; folds 0.333, 0.5, 0.0, 0.4, 0.8 (SD 0.2585); matrix 6/8 and 9/5. This is the lab's most important result, reported as it came out. Thirteen landmarks give 26 coordinates and $2 \times 13 - 4 = 22$ shape dimensions; the pipeline keeps all 22 and fits a 23-parameter regression on 22 or 23 subjects per fold. With as many parameters as subjects the regression draws a boundary through the training set perfectly (training accuracy 1.0 in all five folds) and [Inference] fits noise. Each held-out fold has five or six subjects, so fold accuracy moves in steps of 0.17 or 0.2, and an SD of 0.26 says 0.3929 is not distinguishable from 0.5. Bookstein's own analysis asked a different question: whether the two *mean* shapes differ, tested on the pooled sample, not whether each subject can be assigned to a group [Unverified: the `shapes` documentation only describes the data and cites the paper; neither the 1996 paper nor Dryden & Mardia (2016) was re-read for this chapter]. A mean difference is one vector estimated from 28 subjects; a classifier must generalize from 22. Small $n$ is the whole lesson. [Unverified: not tried] Fewer components or a stronger regularizer than the pipeline's $C = 1$ might lift the number; the lab varies neither, so nothing here says what 28 brains can or cannot support.

Then the baseline: size only scores **0.7857** on the same folds (22 of 28; matrix 11/3 and 3/11; folds 1.0, 0.667, 0.833, 0.8, 0.6, SD 0.1392), with median centroid size 1.69 for controls and 1.56 for patients in the file's units. One number against 28 subjects is a fit the regression cannot overdo, which is part of why it works where 22 numbers failed. [Inference] If that difference is real, the signal in this dataset lives in the scale of the landmark configuration, which the preshape step removes by construction: "shape alone" asked the question in a way that threw the answer away. Two cautions before reading more into it. The fold accuracies run from 0.6 to 1.0, so 0.79 on 28 subjects is a weak estimate, and whether the coordinates share a physical scale across subjects (so that centroid size means head size rather than image scale) is [Unverified] here; the `shapes` documentation does not say. The lab's reading is only that size and shape gave opposite answers on this sample, and that a pipeline that removes size should say so before claiming there is nothing to find.

**Gorilla skulls, female versus male** (59 skulls, 8 landmarks; chance 0.5085). Landmarks + LR: **1.0** in every fold; the worst-mistakes list is empty. Mode 1 explains 46.05 % of the variance and the scatter separates mostly along PC1 (a single PC1 threshold gets about 92 % right; the full 12 components are needed for the rest). Size only is **also 1.0** in every fold (median centroid size 238 for females, 280 for males in the file's units): both shape alone and size alone separate the sexes perfectly, so the lab cannot say which matters more, only that either suffices on these 59. The dataset was collected to study sexual dimorphism in hominoid crania (O'Higgins & Dryden 1993 [Unverified: the paper was not re-read; the `shapes` documentation cites it]), so the lab confirms a known difference rather than discovering one. Two warnings travel with the number: $n = 59$ with 12 shape dimensions is not far from the brain regime, and a perfect score on 59 does not mean a perfect classifier: the one-sided 95 % lower confidence bound for 59 of 59 is 0.95 (the largest accuracy $a$ for which 59 straight successes have probability at most 5 %, $a^{59} = 0.05$, so $a = 0.05^{1/59} \approx 0.950$). A perfect score should also send you back to check the data for leaks before celebrating.

**Leaf outlines, 15 species** (440 leaves, closed outlines; the classical methods see 100 arc-length points, PointNet the 150 of the data file; chance 0.0682). The cyclic-shift test found that 69 % of the outlines already start within 10 % of the perimeter of their best shift, so the file's start point was kept as a landmark; [Inference] the photographs share an orientation and every outline starts at the leaf base. Forcing the alignment anyway was tried while building the lab and dropped the two classical numbers to 0.739 and 0.750 (LAB_SPEC.md records the trial; it is not in the JSON), because whole species were shifted to match a generic mean. Landmarks + LR, 40 components: **0.7932** (SD 0.0253). Spline + LR, 12 control points, 20 components: **0.825** (SD 0.0391), so the spline wins by 0.0318, about one fold SD. Size only: **0.3432** (SD 0.0396), five times chance but far below shape. The size baseline recognizes the two species at the extremes of median size best, *Populus tremula* (median 14.0; 30 of 30 right) and *Sorbus aucuparia* (8.9; 23 of 30), and four species not at all (0 right for *Tilia platyphyllos*, *Prunus padus* and *Scandosorbus intermedia*, 1 for *Acer platanoides* and *Betula pubescens*). The failures of the shape methods are informative: *Sorbus aucuparia* is right only 4 times in 30 on arc-length landmarks and 17 in 30 on the spline, its errors scattered over nine other species on the landmark route and five on the spline route; *Scandosorbus intermedia* is among the next worst (17 of 27 and 16 of 27), and the two are confused in both directions (6 and 1 on the landmark route, 4 and 6 on the spline route). [Inference] Rowan's compound leaf gives a ragged outline that 100 arc-length points place inconsistently, and 12 control points smooth it. PointNet, hold-out: **0.9545**, 5 mistakes on 110 held-out leaves, with the epoch chosen on the select slice at 60 of 60, the last one (`accuracy_select` 0.9697), so more epochs might have helped and the budget did not allow finding out; the untrained twin scores 0.9364 on the same leaves. *Cautionary tale.* The first run reported 0.9818 here, 2 mistakes on 110, with the epoch chosen on those same 110 leaves.

**Red blood cells, sickle-cell disease** (2261 outlines; circular 1637, elongated 489, other 135; chance 0.724). The 2261 is the lab's own extraction, not a dataset count: one outline per connected component of the per-class field masks of erythrocytesIDB2 and 3 (80 fields), with 9 components dropped by an area filter and one IDB2 field that has no circular mask, so "circular" is probably under-counted and chance with it. The license forbids sharing adapted material (ND) and commercial use (NC), so, as a precaution, the lab publishes only counts, accuracies, confusion matrices, fold accuracies, worst-mistake indices with probabilities and the per-epoch selection history: no coordinates, means, modes, scatter, neighbors or weights. To see the shapes, run `python scripts/fetch_datasets.py --rbc` (594 MB, into the git-ignored `data/_local/`), then `python scripts/run_lab.py --dataset rbc`.

This is the dataset the review changed. The contour tracer starts each outline at its top-most pixel, which is meaningless for a cell, and only 24 % of the outlines started near their best cyclic shift, so the alignment was applied: 2224 of 2261 outlines were re-rooted and the mean geodesic distance to the Fréchet mean fell from 0.1469 to 0.1230. Landmarks + LR: **0.9173** (SD 0.0135); spline + LR: **0.9204** (SD 0.0072), the dataset's headline; PointNet hold-out **0.9081** (`accuracy_select` 0.9145, epoch 38 of 40), untrained 0.9046; size only **0.724**, exactly chance, because the extraction's area filter is relative to each database's median cell and leaves the three classes with the same median size (217, 208, 213 px). *Cautionary tale.* The first run, without the shift, gave 0.7859 and 0.7935 for the two classical methods against PointNet's 0.9346, and this chapter read that as "the classical methods earn most of their score by saying circular": 319 of 489 elongated cells were called circular. That was an artifact of the start point, not of the representation; an order-invariant network never saw the problem, and the comparison was unfair by about 0.13. Read the matrices before the accuracies, still. On the landmark route 1594 of 1637 circular cells (97.4 %) and 447 of 489 elongated cells (91.4 %) are right, but "other" is recognized 33 times in 135 (24.4 %; 76 called circular), and the spline route is the same story (34 of 135). "Other" is everything neither round nor elongated; [Inference] a convex region of tangent space, which is what multinomial logistic regression gives each class, is a poor description of a catch-all class. PointNet does somewhat better on its 566 held-out cells (15 of 34 "other", 44 %; 101 of 122 elongated), but "other" is by far the worst class for every method.

Four readings. The classical methods agree closely wherever both run: they are the same geometry on two descriptions of one curve; [Inference] the spline may help when the outline is ragged (leaves) and cost a little when it is already smooth (worms); the leaf gap is about one fold SD and the red-cell gap (0.0031) smaller, so neither is resolved. And the PointNet number is a different kind of number: one split, not five. It is no longer *selected* on the hold-out (the epoch is chosen on a slice of the training part, `best_epoch` 10, 4, 60 and 38 of 40, 60, 60 and 40), but its `accuracy_sd` is still the SD of a 5-fold probe run *inside* the hold-out (`accuracy_cv_val` means 0.887, 0.8867, 0.9, 0.9153; SDs 0.0281, 0.0267, 0.0445, 0.0286), not an uncertainty of the hold-out number, which has none. Treat gaps of up to a few SDs as unresolved.

## Add your own masks

The registry is `shapekit/lab_datasets.py`. A `LabDataset` carries an `id`, `title`, one-line `question`, `representation` (`"landmarks"`, `"outline"` or `"pointcloud"`), a tuple of class names, a `Source` (name, citation, URL, license, redistributed or not), a `loader()` and, for outlines, `closed=True`. The loader returns `(points, labels)`: `points` of shape `(K, N, 2)`, points as rows and `(x, y)` as columns; `labels` of shape `(K,)`, integers from 0 to the number of classes minus 1. The simplest layout is an npz in `data/` with keys `points` and `labels`, read by `_npz_loader("<id>_outlines.npz", "--<id>")`; Chapter 01's `shapekit.contours.mask_to_landmarks` and `resample_by_arclength` get you from a mask folder to that array. A closed outline gets the cyclic-shift test automatically. Add the entry to `DATASETS`, then

```bash
python scripts/run_lab.py --dataset <id>                                 # writes docs/lab/data/<id>.json (+ models/<id>.onnx)
python scripts/run_lab.py --dataset <id> --skip-pointnet --out /tmp/lab  # classical only, seconds; refuses the default folder without --force
```

and reload the lab: card, panels and classify screen appear with no page code. Set `shapes_shown=False` if the license forbids publishing derived coordinates; the exporter then strips every shape and weight.

## Limits and honesty notes

- **One seed.** Another seed moves the folds and the PointNet split. The fold SDs (0.0071 on worms, 0.0253 and 0.0391 on leaves, 0.0135 and 0.0072 on red cells, 0.2585 on brains) are the only spread estimate on the page; the PointNet hold-out number has none.
- **Chance is the largest class.** On the red cells that is 0.724, the size baseline sits exactly there, and the per-class rows matter more than the total.
- **No hyperparameter search.** $C = 1$, at most 40 components, M = 6 or 12, Chapter 08's recipe, 40 or 60 epochs. Tuning would raise some numbers; on the leaves the chosen epoch was the last one, so the budget is visibly binding there.
- **PointNet is not "shape alone".** Its input now has size removed (each cloud divided by its own RMS radius), but [Inference] training-time rotations remove most but not all orientation (the lab measures permutation invariance, not rotation sensitivity). Only the classical columns measure shape in Kendall's sense.
- **Size is measured, not combined.** The size baseline is a separate method; nothing in the lab adds size to a shape model, so "shape and size together" is a number the lab does not have.
- **Correspondence is a decision.** The cyclic-shift test is label-free, but its threshold (half of the outlines within 10 % of the perimeter) is a choice; the leaves show that forcing the alignment can cost 0.05 to 0.08 of accuracy when the source's start is a real landmark.
- **Small n.** 28 and 59 are illustrations, not evidence either way.
- **The lab cannot see confounds.** Cross-validation and a hold-out each check only that a rule generalizes to new shapes from the same groups. Neither checks that the label is the only thing that differs between the groups. On MEF it is not: genotype travels with substrate and with whatever else differs between the two source folders, so no MEF number on the page can be attributed to genotype. The other five datasets were not audited this way. [Inference] The worms are a milder case of the same pattern: live and dead come from treated and untreated wells, so well and treatment travel with the label by design of the assay.
- **Licenses differ.** Worms BSD-3 over CC0, cells MIT, brains and gorillas GPL-2, leaves CC BY 4.0, red cells CC BY-NC-ND 4.0 and therefore never published. Reusing a dataset means inheriting its terms.

## Try it

Reproduce the gorilla row from the repository root (the registry tells you the fetch command if a file is missing).

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from shapekit.lab_datasets import DATASETS
from shapekit.preshape import preshape, to_complex
from shapekit.shape_space import frechet_mean
from shapekit.tangent_pca import TangentPCA

points, labels = DATASETS['gorilla'].load()          # (59, 8, 2), 0 = female, 1 = male
Z = to_complex(preshape(points))
pca = TangentPCA(mean=frechet_mean(Z)).fit(Z)
X = pca.transform(Z)[:, :12]                          # 2*8 - 4 = 12 shape dimensions
clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=3000))
cv = StratifiedKFold(5, shuffle=True, random_state=0)
print(cross_val_score(clf, X, labels, cv=cv))         # expect [1. 1. 1. 1. 1.]
print(np.round(pca.explained_variance_ratio_[:3], 3)) # expect 0.46 0.169 0.106
size = np.log(np.linalg.norm(points - points.mean(1, keepdims=True), axis=(1, 2)))
print(cross_val_score(clf, size[:, None], labels, cv=cv))  # size only: also [1. 1. 1. 1. 1.]
```

Swap `'gorilla'` for `'brain'` and `12` for `22` to watch the same code lose to chance (folds 0.333, 0.5, 0.0, 0.4, 0.8) while the size line scores 1.0, 0.667, 0.833, 0.8, 0.6.

## Check yourself

<details><summary>1. The brain classifier scores 0.39 with chance at 0.5. Is the method broken?</summary>
No. With 22 components and 22 or 23 training subjects per fold the regression fits the training set perfectly and generalizes at random; folds of five or six subjects land anywhere, as the fold SD of 0.26 shows. The fix is more subjects, fewer components, or a different question (do the mean shapes differ? does size differ? it scores 0.79 on the same folds), not a different classifier.
</details>

<details><summary>2. PointNet tells the two MEF groups apart at 0.917 from outlines alone. Is that a lamin A/C phenotype?</summary>
Not on this evidence. First ask what else differs between the groups. Here it is the substrate, and whatever else differs between the two source folders: every sampled wild-type field comes from `Control/LMNA++1` (unpatterned) and every sampled LMNA−/− field from `Circle/LMNA--1` (circle micropattern). Circularity and axis ratio alone score 0.94 (5-fold CV, against PointNet's 0.917 hold-out). [Inference] Roundness, which the pattern would be expected to impose on any cell, is enough to reach the same accuracy, so the result cannot be read as genotype. The test that separates the two explanations is wild-type versus LMNA−/− on the same substrate, which the original repository makes possible. The same habit applies to a margin, such as PointNet's 0.077 over the landmark route on the worms. Ask whether the two numbers are the same kind (here a hold-out against a cross-validated one), what an untrained twin scores (0.8725, so training added about two worms), where the epoch was chosen (the first run chose it on the hold-out it reported), and what the input kept (the first run kept size).
</details>

<details><summary>3. On the red cells the landmark method went from 0.786 to 0.917 between the two runs with no change to the classifier. What changed?</summary>
The correspondence. Arc-length points on a closed outline are in correspondence only up to a cyclic shift, and the traced outlines all started at the top-most pixel of the cell; re-rooting each outline at the shift closest to the Fréchet mean fixed it (2224 of 2261 shifted). The same step was not applied to the leaves, whose outlines already start at the leaf base, because forcing it there costs accuracy. Read the per-class rows either way: "other" is still recognized only 24 % of the time.
</details>
