# Build spec: Shape Analysis Field Guide

This file is the single source of truth for everyone building the repo. Read all of it before writing
anything. If you must deviate, record the deviation at the bottom under "Deviations".

## Purpose and reader

A private learning repository for one reader: a biologist (microscopy / image analysis background, not a
computer scientist) who wants to **understand** shape analysis well enough to **implement** it in future
projects. The material adapts the EMBL-EBI "Shape Analysis 101" tutorial
(github.com/uhlmanngroup/shapeanalysis101, BSD-3, Hugger & Uhlmann 2021) into a self-contained,
pleasant-to-read field guide. A full plain-language walkthrough of that tutorial, including its bugs,
is at `/home/user/GLOBIAS-2026-GROUP-5/docs/shapeanalysis101_explained.md` — read it for the concepts,
formulas and findings; it is reliable.

Tone: calm, concrete, friendly, no hype, no flattery. Short paragraphs. Analogies welcome when they are
exact. Every formula is followed by a plain-language reading of each symbol and a pointer to where it
lives in `shapekit/`. Label anything not established as fact with **[Inference]** or **[Unverified]**.
Never present guessed numbers as results.

## Visual identity (used by figures AND site)

Light theme: paper `#FAF7F2`, surface `#FFFFFF`, ink `#1F2A37`, muted `#5B6673`, line `#D9D4CC`.
Dark theme: paper `#141820`, surface `#1C222C`, ink `#E8E6E1`, muted `#9AA3AE`, line `#2C3440`.
Accents (same in both): **teal `#1B998B`**, **coral `#E4572E`**, gold `#F2A541`, lavender `#7B6CF6`, slate `#6B7A8F`.
Class colours, always: class 0 (dead worm / wild-type cell) = **coral**; class 1 (live worm / LMNA-/-) = **teal**.
Mean shapes = ink; "before" states = slate at 50 % alpha; highlights = gold.
Fonts: headings "Fraunces" (Google Fonts, fallback Georgia), body "Inter" (fallback system sans), code "JetBrains Mono".
Figures: matplotlib, transparent-free paper background `#FAF7F2`, no top/right spines, dpi 160, width 1200 px
(or 1600 for wide ones), font sizes ≥ 11 pt, equal aspect for shapes, y-axis inverted for image coordinates
(so worms look like they do in the image). GIFs: 12 fps, ≤ 3 MB each, loop forever, last frame held 1 s.

Chapter conventions:
- Front matter line 1: `# NN · Title`. Then a 2–3 sentence "In one breath" summary in a blockquote.
- End every chapter with: "**Try it**" (a 5–15 line runnable `shapekit` snippet), "**Check yourself**" (3 questions
  with collapsed answers using `<details>`), and "**Next**" link.
- Math: GitHub-flavoured `$inline$` and `$$ display $$` on their own lines. After each display formula, a
  bulleted "reading it" legend. Avoid `\|` inside `$…$` (GitHub mangles it; write `\lVert z \rVert`).
- Figures: `![alt](../figures/NAME)` followed by an italic one-line caption. Interactive demos are embedded as
  `<div class="demo" data-demo="NAME"></div>` right after the related static figure (so GitHub readers get the
  static version and site readers get the live one).
- Code references: write "`shapekit.procrustes.optimal_rotation_angle`" style names; the engineer guarantees
  these exist with those signatures (see API below).

## shapekit API (engineer guarantees; writers may cite)

```python
# preshape.py
center(X) -> X - centroid                      # X: (N,2) or (K,N,2)
normalize(X) -> X / Frobenius norm             # same shapes
preshape(X) -> normalize(center(X))
to_complex(X) -> (N,) or (K,N) complex ; from_complex(z) -> (...,2)
# procrustes.py
optimal_rotation_angle(z, w) -> float          # angle(conj(z)·w): rotates z onto w
align(z, w) -> rotated z
align_dataset(Z, ref) -> Z aligned to ref
gpa_mean(Z, n_iter=20, seed=0, return_history=False)
# shape_space.py
frechet_mean(Z) -> (N,) complex preshape
geodesic_distance(z, w), procrustes_distance(z, w), chord_distance(z, w)
geodesic_path(z, w, n_steps=10) -> (n_steps+1, N)
log_map(mean, z) -> tangent vector ; exp_map(mean, v) -> preshape
# tangent_pca.py
TangentPCA(mean=None).fit(Z) ; .transform(Z) -> scores ; .explained_variance_ratio_ ;
  .mode_shape(i, n_sd=1.0) -> (+shape, -shape) ; .sample(n, n_modes, seed) -> shapes
# bspline.py
cubic_bspline(x) ; interpolation_filter(samples, closed=False) ; BSplineCurve(M, closed).fit(points).sample(k)
gram_matrix(M)
# contours.py
mask_to_contours(mask, min_len) ; order_skeleton(mask) ; resample_by_arclength(points, N)
# embed.py (torch optional)
PointNet(embed_dim, proj_dim) ; SupConLoss(temperature) ; linear_probe_accuracy(features, labels)
# datasets.py
load_celegans() -> (points, labels) ; load_mef_subset() -> (points, labels, keys)
```

Every public function has a docstring that (1) states the formula, (2) explains each symbol in plain words,
(3) names the chapter that explains it. Axis convention everywhere: **points are rows, (x, y) are columns**:
shape `(N, 2)`, dataset `(K, N, 2)`. Say so in `shapekit/__init__.py`.

## Deviations

(record here)

### shapekit / tests / export_site_data (Python engineer)

- `gpa_mean` has an extra keyword `weighted=True`. The default multiplies each shape by the full inner
  product `conj(z)·m` (rotation **and** scale), which is exactly power iteration on `Σ z zᴴ` and
  converges to `frechet_mean` to < 1e-6 from any seed (tested). `weighted=False` is textbook,
  rotation-only GPA; it converges to the same fixed point from any start but that point lies
  0.0070 rad (geodesic; 0.0070 Procrustes distance) from the eigenvector mean on the worm data. The
  "re-computed 1e-5 agreement" in `shapeanalysis101_explained.md` §5.2 holds for the weighted loop,
  not for rotation-only GPA. Chapter 05 should say so. With `return_history=True` every iterate is
  returned already rotated onto the final mean.
- `frechet_mean` fixes the arbitrary rotation of the eigenvector with
  `shapekit.procrustes.canonical_orientation` (long axis horizontal, first landmark on the left) so
  means, PCA modes and figures are reproducible. This is a convention, not a change of shape.
- Extra public helpers beyond the API table, all documented in the same style: `frobenius_norm`,
  `hermitian_product`, `rotate`, `canonical_orientation`, `tangent_to_real`/`real_to_tangent`,
  `TangentPCA.inverse_transform` and attributes `mean_`, `mean_tangent_`, `components_`,
  `explained_variance_`, `sdev_`; `basis_matrix`, `BSplineCurve.evaluate/knots/t_fit_`,
  `gram_matrix(M, closed=True)`; `skeletonize` (Zhang–Suen, so chapter 01 needs no scikit-image),
  `skeleton_endpoints`, `arc_length`, `mask_to_landmarks`; `datasets.resolve_data_dir`
  (`SHAPEKIT_DATA` env var or `data_dir=` argument).
- B-spline convention: `BSplineCurve(M, closed)` has exactly **M** control points. Open curves use
  mirror boundary conditions (`c[-1] = c[1]`, `c[M] = c[M-2]`, parameter `t ∈ [0, M-1]`), not the
  tutorial's padded `M + 4` coefficients; both pass through the same knots. `fit(points)` interpolates
  exactly when `len(points) == M` (recursive filter, pole −2+√3) and otherwise does a least-squares fit
  with arc-length parameters. `sample(n_points)` takes a number of points, not a per-segment rate.
  `gram_matrix` integrates over `t ∈ [0, M)` (closed) / `[0, M-1]` (open), i.e. the tutorial's Φ
  times M.
- Tangent vectors are stored as 24 reals: 12 x-parts then 12 y-parts (`tangent_layout: re_then_im`
  in `worms.json`). `TangentPCA.sample` uses `sdev_` directly (no `√(n−1)` factor).
- `docs/data/spline.json`: the dataset has only 12 landmarks per worm and no raw mask, so the "20
  landmarks" are worm 0's 12 points interpolated by a cubic B-spline, densely sampled and resampled to
  20 points by arc length. The file also carries `curve` (101 samples), `closed`, `boundary`, `M` and
  `twelve_landmarks`. `worms.json` carries extra keys `note`, `n_landmarks`, `examples.indices` and
  `pca.tangent_layout`; `examples` keep their image orientation (unaligned preshapes), `class_means`
  are rotated onto `mean`.
- `celegans_labels.npy` is stored as float64; `load_celegans` returns it as int.

### Site (docs/index.html, style.css, app.js, demos/)

- **Shared demo helper.** Besides one file per demo, `docs/demos/_lib.js` holds the shared SVG builders,
  pointer-drag helper, slider/button widgets, the preshape/rotation maths and the built-in sample shapes.
  Each demo still has its own file with a default `mount(el, ctx)` export.
- **Text-safe accent shades.** Teal `#1B998B` and coral `#E4572E` sit below 4.5:1 on the light paper, so
  for *text* (links, readouts, legends) the site uses `--teal-text #0F766E` / `--coral-text #B8411F` in light
  mode (`#3DBFAF` / `#F0785A` in dark). Graphics (strokes, dots, swatches) use the SPEC accents unchanged.
- **Hash routes carry section anchors**: `#06` opens a chapter, `#06/modes-of-variation` jumps to a heading.
  Links to other chapters written as `03-rotation-and-complex-numbers.md` are rewritten to `#03`.
- **"In one breath" label.** The writers put the bold "In one breath." inside the blockquote themselves, so
  the site only styles that first blockquote as a lede callout and adds its own label only when the text
  does not already start with those words.
- **pca-modes** shows `exp_map(mean, mean_tangent + Σ wᵢ sᵢ cᵢ)`, i.e. it adds the exported `mean_tangent`
  (≈ 0 at the Fréchet mean) to the SPEC formula so the reconstruction matches `TangentPCA` exactly.
- **contrastive** is a toy: 16 points in the plane (not on a unit sphere, where a 2-D picture would collapse
  to a circle), similarity `−2‖zᵢ − zⱼ‖²` in place of the cosine, the exact SupCon loss and its gradient
  direction, and a fixed step length so every temperature stays watchable. The loss readout is the real
  SupCon value for the toy configuration, not a training result.
- **rotate-align** draws B deliberately turned 70° away from A at the start; the error-curve panel and
  per-landmark error ties are additions beyond the SPEC row.
- **Keyboard ←/→** are ignored while focus is inside a demo (range sliders need the arrow keys).
- Demos running on built-in sample shapes show a "built-in sample shapes" badge so illustrative numbers are
  never mistaken for results.
